直近の測定の失敗を1件ずつ原記録で判定してください。

1. 渡された通常測定と最終測定のうち直近の報告を選び、実行日時と保存先を確認してください。Report Directory にある前回の `pe-classification.md` とその履歴も開いてください。
2. 不合格ごとに元のイベントファイル、出力全文、採点理由、終了理由を開いてください。報告の引用や要約だけで判定しないでください。
3. 変更前に期待どおり起きた失敗と、変更後の失敗を分け、同じ条件の独立実行で同じ機序が2回連続したかを照合してください。初回だけの失敗は修正候補として確定せず、同条件の再測定を指定してください。
   変更前で狙いどおり起きた規則違反は比較の証拠です。それだけを理由に候補を修正したり、候補の失敗として再測定を要求したりしないでください。
4. 修正を判断できる件は、プロンプトの穴、eval の不備、変更前でも合格して弁別できないケースに分け、元記録の位置と短い原文、判定理由、必要な修正を記録してください。制限時間の終了は停止側と直前の正しい行動まで確かめてください。
5. 変更前でも合格したケースは、実 run の構造へ fixture を近づける案があるかを示してください。案がない、または弁別を目的としないものは回帰ガードと記録してください。
6. 複数種類が混在するときは、単発失敗の同条件再測定を先に指定し、次に確定したプロンプトの穴、次に eval の不備を扱ってください。未処理の件を全て残してください。すべて解消するまで完了扱いにしないでください。
7. 原記録がなく判定できない件、範囲外の実装が必要な件は理由と不足を明記してください。ファイルの恒久的な修正はしないでください。

`pe-classification.md` に各件の連続回数、条件、分類、根拠、次に行う作業と未処理事項を残してください。
