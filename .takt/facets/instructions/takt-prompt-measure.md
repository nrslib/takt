比較元と改修後で対象 eval を測定し、実際の出力と採点理由を記録してください。

1. 渡された `takt-prompt-plan.md` の対象スイート・provider・比較元 SHA・切替対象と、直近の切り分け報告を読んでください。測定範囲や文面を独断で変えないでください。
2. 入力のコピーを作成する間に、編集やビルドが並行して行われないことを確認してください。`npm run build` を済ませてから、計画に挙げた全ファセットと必要な workflow 参照を明示して比較してください。
3. 通常の runner を使える場合は `node eval/scripts/compare-facets.mjs --base <確定SHA> --suite <suite> --facet <path> --output-dir <新規保存先>` を使ってください。suite と facet は必要なだけ繰り返せます。専用スイートでは、計画に記した既存の比較手順を使ってください。

   | オプション | 使う場面 |
   |------------|----------|
   | モード指定なし | 変更前と変更後の両方を測定する（既定） |
   | `--mode green` | 同じ条件の候補だけを再測定する |
   | `--filter-providers <regex>` | 切り分け中に対象を絞って測定する |

4. キャッシュの再採点を独立した試行に数えないでください。ファイルを編集する eval では、各試行で新しい fixture を用意してください。比較中は入力・fixture・rubric・provider 設定を変更前後でそろえてください。
5. 保存された結果 JSON の全行について、出力全文と採点理由を読んでください。不合格やエラーは各行の `response.metadata.execution_record` から provider の元のイベント・出力・終了理由を開いて確認してください。専用 provider はその保存経路を使ってください。ログの先頭や抜粋だけでは原因を確定しないでください。
6. ケース・provider ごとに、次の内容を報告してください。前の測定も保存先を残して追跡してください。
   - 比較元と候補、実行コマンド、終了コード
   - 結果 JSON、eval ID、生ログの位置
   - 実際の行動と採点理由
7. manifest にある各実行の workspace と結果の保存先、測定した文面と比較条件を記録してください。未実行の場合や元の記録が不足している場合は、合格にしないでください。

出力契約で指定された測定報告に、実行単位ごとの結果と根拠を残してください。
