# ファセット差分の判定

意味と言語の自然さを保ち、判断規則を正しい所有者へ置く。

## 原則

| 原則 | 基準 |
|------|------|
| 等価性 | 日本語と英語で条件・禁止・必須対応・例外が一致する |
| 自然な日本語 | 直訳調、詰め込んだ言い回し、造語を避ける |
| 所有者 | 判断規則の正本を一つにする |
| 到達性 | 必要な担当へ include と workflow の参照が届く |
| 範囲 | 承認された設計に必要な差分だけを作る |

## 文面と分類

| 基準 | 判定 |
|------|------|
| 翻訳で発火条件が広がる、禁止が弱まる、例外が抜ける | REJECT |
| 普通の文章で言える内容に新たな分類名や略称を付ける | REJECT |
| 主語が曖昧、抽象語を重ねる、不自然な直訳で対応が分からない | REJECT |
| identity・専門性・責任境界を persona に置く | OK |
| 原則・禁止・判断基準を policy に置く | OK |
| 記述的な知識と判断材料を knowledge に置く | OK |
| その場の操作・順序・探索の開始と停止を instruction に置く | OK |
| 記録形式を output contract に置く | OK |
| 同じ判断規則を複数の種類へ転記する | REJECT |
| 別の段階だけが読むファセットを、現在の担当も知っていると仮定する | REJECT |

## 差分の範囲

| 基準 | 判定 |
|------|------|
| 累積差分に、承認された規則や評価と無関係な変更がある | REJECT |
| 製品コードや新しい評価機構を必要とする変更を混ぜる | REJECT |
| 文面を変えたのに、対応する言語・読む担当・受け渡す報告が追従していない | REJECT |
| 旧版でも合格する評価の限界を明記する | OK |
