# ファセット差分の判定

意味と言語の自然さを保ち、判断規則を役割に合った種類のファセットに置く。

## 原則

| 原則 | 基準 |
|------|------|
| 意味の一致 | 日本語と英語で条件・禁止すること・必ず行うこと・例外が一致する |
| 自然な日本語 | 直訳調、詰め込んだ言い回し、造語を避ける |
| 規則を置く場所 | 判断規則の本体を置く場所を一つにする |
| 読む担当への参照 | include と workflow の参照を通じて、必要な担当が規則を読めるようにする |
| 範囲 | 承認された設計に必要な差分だけを作る |

## 文面と分類

| 基準 | 判定 |
|------|------|
| 翻訳で規則が当てはまる条件が広がる、禁止が弱まる、例外が抜ける | REJECT |
| 普通の文章で言える内容に新たな分類名や略称を付ける | REJECT |
| 主語が曖昧、抽象語を重ねる、不自然な直訳で対応が分からない | REJECT |
| 役割・専門性・担当の範囲を persona に置く | OK |
| 原則・禁止・判断基準を policy に置く | OK |
| 記述的な知識と判断材料を knowledge に置く | OK |
| その場の操作・順序・調査の始め方と止め方を instruction に置く | OK |
| 記録形式を output contract に置く | OK |
| 同じ判断規則を複数の種類へ転記する | REJECT |
| 別の段階だけが読むファセットを、現在の担当も知っていると仮定する | REJECT |

## 差分の範囲

| 基準 | 判定 |
|------|------|
| 開始時からの差分に、承認された規則や評価と無関係な変更がある | REJECT |
| 製品コードの変更や新しい評価の仕組みが必要になる変更を混ぜる | REJECT |
| 文面を変えたのに、対応する言語の文面・読む担当への参照・受け渡す報告を合わせていない | REJECT |
| 変更前の文面でも合格する評価の限界を明記する | OK |
