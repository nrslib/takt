# 二つの宛先へ送る

二つの異なる宛先へ、独立してメッセージを送る小さなReactアプリです。送信処理は外部サービスへ接続せず、画面内のタイマーで約1秒後に成功または失敗を反映します。

## 起動方法

依存関係は用意済みですが、初回にインストールする場合は次を実行します。

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。プロダクションビルドは次で作成できます。

```bash
npm run build
```

## 操作方法

- 各カードの入力欄へ本文を入力し、「送信する」を押します。
- `Ctrl + Enter` または `Command + Enter` でも送信できます。通常の `Enter` は改行です。
- 空白だけの本文は送信されず、入力欄の下に理由が表示されます。
- 送信中はそのカードの入力欄と送信操作が停止します。もう一方のカードは操作できます。
- 「入力を消去」ではカード内に確認が表示されます。「編集に戻る」なら本文を保持し、「破棄して消去」なら本文を消します。
- 「次の送信を失敗させる」を選んでから送信すると、一度だけ失敗します。本文は残るため、そのまま再送信できます。
- ヘッダーまたは各カードの `?` ボタンから操作説明を開けます。`Escape`、閉じるボタン、背景クリックで閉じられます。

## 実装した設計

- `App`を画面のRoot兼Mediatorとし、`useReducer`で二つの宛先の下書き、確認中、送信状態、結果、受付回数、失敗予約を一元管理しています。宛先IDは`project`と`support`に固定し、兄弟カードが別々に対象識別子を持たないようにしています。
- `DestinationCard`は受け取ったstateを表示し、入力変更・送信・消去確認・失敗予約・説明表示の意図をcallbackで上位へ通知するPassive Viewです。フォーム送信とショートカットは同じ`onSend`へ入り、送信可否を`App`で一度だけ判定します。
- 送信のタイマーはイベントハンドラで開始し、結果だけをreducerへdispatchします。宛先ごとの処理中集合とreducerの状態確認で、同じ宛先の連打を一回に制限します。タイマーはunmount時にcleanupします。
- 消去確認はカード内の状態として表示します。操作説明だけは、背景を`inert`にしてフォーカスを内部へ閉じ込める共通ダイアログにしています。閉じた後は開く前のボタンへフォーカスを戻します。

## criteriaとの関係

提供された6文書を次のように適用しました。

- `knowledge-gui.md`: Rootから画面・カードへpropsとcallbackを渡し、共有状態をAppに置き、表示部品とMediatorの責務を分離しました。
- `knowledge-frontend.md`: `label`と入力欄を関連付け、送信状態・失敗・再試行を表示し、入力値をHTMLとして挿入せずテキストで描画しました。URL保持や外部通信は仕様外のため追加していません。
- `knowledge-react.md`: `useReducer`を純粋な状態遷移に使い、副作用をイベントハンドラへ置き、二つのカードを安定した宛先IDで描画しています。
- `policies-gui.md`: 送信中・確認中に対象カードだけを停止し、独立したもう一方は操作可能にしました。クリック、フォーム、キーボードは同じMediatorの判定を通ります。
- `policies-frontend.md`: 適切な`button`・`label`・`disabled`・`aria-*`を使い、操作説明ダイアログのフォーカス移動、フォーカストラップ、背景抑止、復帰を実装しました。
- `policies-react.md`: 兄弟間の状態を親へ集約し、reducerにタイマー処理を入れず、送信タイマーのcleanupと状態に応じた操作拒否を実装しました。

## 検証

- `npm run build`でTypeScriptチェックとViteビルドが成功することを確認しています。
- 実装上、送信ボタンとキーボード送信が同じ処理へ入ること、空白入力・送信中の連打・失敗後の再試行・カード内消去確認・説明ダイアログのフォーカス制御を確認しました。
