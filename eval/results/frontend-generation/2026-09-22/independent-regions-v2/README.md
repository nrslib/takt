# Relay — 二つの宛先へのメッセージ送信

## 起動方法

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザで開きます。配布用ビルドは `npm run build` です。

## 操作方法

- 「制作チーム」と「サポート窓口」に、それぞれ別の本文を入力して送信できます。
- 通常のEnterは改行、Ctrl + Enter または Command + Enterは送信です。
- 空白だけの本文は送信されず、入力欄の下に理由が表示されます。
- 送信中は対象の入力欄がロックされます。もう一方の宛先は独立して入力・送信できます。
- 「入力を消去」では欄内に確認を表示します。「編集に戻る」なら本文を残し、「破棄する」で本文を消します。
- 「次の送信を失敗させる」を設定すると、その宛先の次の送信だけ失敗します。失敗時は本文が残り、同じ送信ボタンから再試行できます。
- ヘッダーまたは各カードの「操作ガイド」から同じ説明ダイアログを開けます。Escまたは閉じるボタンで閉じられます。

## 実装した設計

- `App`がRootとして二つの`MessageCard`を組み立て、表示部品には値と操作通知だけをpropsで渡しています。
- `useMessageMediator`の`useReducer`が宛先ごとの草稿、確認、送信中、成功、失敗、失敗予約、受け付け回数を一元管理します。フォーム送信とショートカットは同じ送信ハンドラへ集約しています。
- 送信完了の約1秒タイマーはハンドラで開始し、reducerは状態遷移だけを担当します。宛先IDごとのロックで連打を拒否し、片方の状態がもう片方へ影響しないようにしています。
- 成功時は実際に送った本文をテキストとして表示し、失敗時は草稿を保持します。入力内容をHTMLとして挿入する処理や外部API、URL・Storageによる状態保持はありません。
- 操作ガイドは`role="dialog"`と`aria-modal="true"`を使い、開いたときに閉じるボタンへフォーカスし、Tab循環・Esc閉じる・起点へのフォーカス復帰を実装しています。背景はスクリーンとキーボードイベントで操作できない状態にしています。入力消去の確認は仕様どおり各カード内に表示する非全画面の確認です。

## 6文書との関係

`criteria/knowledge-gui.md`と`criteria/policies-gui.md`に合わせ、Rootから表示部品と処理担当をたどれる構成にし、状態に応じて操作を受理・拒否するMediatorを画面側へ置きました。

`criteria/knowledge-frontend.md`と`criteria/policies-frontend.md`に合わせ、ボタン・フォーム・ラベルを意味どおりに使い、送信中・成功・入力不備・失敗を区別して表示しています。ダイアログのフォーカス制御と背景操作の抑止も実装しました。

`criteria/knowledge-react.md`と`criteria/policies-react.md`に合わせ、兄弟カードの共有状態を親のreducerに集約し、派生表示は描画時に計算しています。タイマーはreducer外で開始し、アンマウント時にcleanupします。入力値はpropsで制御し、副作用のある操作をEffectへ移していません。

## 検証したこと

- `npm run build`（TypeScriptの型検査とViteビルド）
- 送信ボタンとCtrl + Enter / Command + Enterが同じ送信経路を通ること
- 空白だけの送信拒否、宛先ごとの送信中ロック、約1秒後の成功表示
- 宛先ごとの失敗予約・一度だけの失敗・本文保持・再試行
- 入力消去の確認、編集復帰、宛先間の独立操作
- 操作ガイドの共通内容、フォーカス移動・復帰、Tab循環、Esc閉じる
