# 実装課題：問い合わせへの返信を編集する画面

小規模な問い合わせ対応用のWebアプリを作ってください。React、TypeScript、Viteを使用します。依存関係はインストール済みです。日本語の画面とREADMEを作成してください。

## 利用者ができること

- 初期状態で、件名、問い合わせ本文、保存済みの返信を持つ問い合わせを3件以上表示する。一覧から選んだ問い合わせの本文と返信編集欄を表示する。
- 返信を編集して保存できる。保存はボタンと Ctrl+Enter / Command+Enter の両方から行える。入力欄で通常のEnterを押すと改行する。
- 空白だけの返信は保存せず、修正が必要なことを表示する。
- 保存には約1秒かかる。その間に繰り返し保存操作をしても、保存処理は一回だけ行う。保存中の対象切替は受け付けず、その理由が利用者に分かるようにする。
- 保存成功後は、一覧と詳細が新しい内容を表示する。保存前後や失敗後の状態が分かるようにする。
- 未保存の編集がある状態で別の問い合わせを選ぶ場合は、編集を破棄するか、切替をやめるか選べる。切り替えた後に別の問い合わせの入力が混ざらない。
- 返信を保存済みの内容へ戻す操作がある。
- ヘッダーと返信編集欄の両方から、同じ操作説明ダイアログを開ける。閉じたら元の操作を続けられる。
- 一覧は検索でき、該当する問い合わせがない場合も分かる。ページ再読込後の保存内容の保持や、URLによる対象指定は不要。

## 実演用の条件

外部サービスは不要です。保存はローカルの非同期処理で再現してください。「次の保存を失敗させる」操作を用意し、一度失敗した後に再試行して成功できるようにしてください。失敗時は編集内容を保持します。

連打時の実行回数を確認できるよう、受け付けた保存処理の累計回数を実演用の小さな表示に出してください。受け付けなかった操作では増やさず、受け付けてから失敗した保存は一回と数えます。

## 提供した設計基準と作業条件

criteria/ 配下の6つのMarkdownだけを、この実験の追加の設計基準として使ってください。knowledgeとpoliciesにはそれぞれGUI、frontend、Reactがあります。frontendの先頭の {extends:gui} は同じ種別のGUI文書を併せて読むという意味です。6文書はそのまま適用し、元の文書は編集しないでください。

$coding を参照しないでください。SKILL.md、その他のスキル、AGENTS.md、過去の会話、他プロジェクト、評価問題や模範解答を参照しないでください。プロジェクト内の仕様、criteria、インストールされた依存の実装・型は参照できます。Web検索は不要です。subagentは使用しないでください。

コンポーネントの分割、状態の置き場所、操作の処理方法、識別子の名前は、自分で設計してください。設計パターンを説明するだけでなく、実行できるコードを完成させてください。不要な機能は増やさないでください。

npm run build が成功することを確認してください。READMEには起動方法、操作方法、実際に選んだ設計と6文書との関係、検証したことを記載してください。自分で発見した問題はこのセッション内で修正できます。最終回答は簡潔にしてください。
