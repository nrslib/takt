# Reply Desk

問い合わせへの返信を編集・保存するためのReact / TypeScript / Vite製の小規模な画面です。外部サービスは使わず、保存処理をローカルの非同期処理で再現しています。

## 起動方法

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。プロダクションビルドは次で作成できます。

```bash
npm run build
```

## 操作方法

- 左の受信トレイから問い合わせを選択します。件名・本文・顧客名・返信内容で検索できます。
- 返信欄を編集し、「返信を保存」を押すか、`Ctrl + Enter` / `⌘ + Enter` を押して保存します。通常のEnterは改行になります。
- 空白だけの返信は保存できません。
- 保存中は約1秒かかり、保存の再実行と問い合わせの切替は受け付けません。保存処理を受け付けた回数は「受付済み保存」に表示されます。
- 未保存の編集がある状態で問い合わせを切り替えると、編集を続けるか、編集を破棄して切り替えるかを選べます。
- 「保存済みに戻す」で現在の返信を最後に保存された内容へ戻せます。
- ヘッダーまたは返信欄の「操作説明」から同じ説明ダイアログを開けます。ダイアログを閉じると、開く前のボタンへフォーカスが戻ります。
- 「次の保存を失敗させる」を有効にすると、次に受け付けた保存だけが失敗します。失敗後は編集内容を保ったまま再試行できます。

## 選んだ設計

- `App`をRootとして、`InquiryList`、`InquiryDetail`、`ReplyEditor`、ダイアログを組み合わせています。
- 問い合わせ一覧、選択中の識別子、返信の下書き、保存中かどうか、保存結果、切替確認対象は、画面の動作を調整する`useInquiryDesk`に集約しました。同じ事実を複数部品で持たせず、一覧と詳細が同じ問い合わせデータを参照します。
- `InquiryList`や`ReplyEditor`はpropsを描画し、選択・編集・保存などの意図をcallbackで上位へ通知するPassive Viewです。保存、入力検証、未保存切替、保存中の操作拒否はhook内のhandlerが現在状態を見て判断します。
- 保存の副作用は操作handlerから開始し、`setTimeout`で約1秒後に成功または失敗を反映します。失敗フラグは保存受付時に取り込み、保存受付回数も受付時だけ増やします。タイマーはunmount時にcleanupします。
- URL、Web Storage、外部APIは使っていません。課題で不要とされているため、画面状態は再読込で初期化されます。

## 6文書との関係

`criteria/`配下の6文書を追加の設計基準として適用しました。元の文書は変更していません。

- `knowledge-gui.md` / `policies-gui.md`: Rootからの部品階層、Passive View、Mediatorとしての画面用hookを採用しました。クリック、フォーム送信、キーボード入力は同じ保存handlerを通ります。
- `knowledge-frontend.md` / `policies-frontend.md`: label付きの入力、意味に合うbutton、検索結果が空の場合の表示、保存中・成功・失敗・入力不備の区別、dialogのrole・フォーカス移動・Escape閉じる操作を実装しました。入力内容はHTMLとして挿入せず、テキストとして表示しています。
- `knowledge-react.md` / `policies-react.md`: 下書きをcontrolled inputとして管理し、一覧の派生値は描画時に計算しています。保存の副作用はhandlerに置き、タイマーのcleanupを`useEffect`で行い、一覧のkeyには問い合わせの安定した`id`を使っています。
