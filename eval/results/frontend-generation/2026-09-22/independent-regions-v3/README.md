# DUO MESSAGE DESK

二つの独立した宛先へ、同じ画面からメッセージを送る小さなReactアプリです。送信処理は外部サービスへ接続せず、画面内のタイマーで約1秒後に完了します。

## 起動方法

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザで開いてください。プロダクション用の確認は次で実行できます。

```bash
npm run build
```

## 操作方法

- 「企画チーム」と「カスタマーサポート」の入力欄へ、それぞれ本文を入力します。
- 「送信する」または `Ctrl + Enter` / `Command + Enter` で、その宛先だけを送信します。通常の `Enter` は改行です。
- 空白だけの本文は送信できず、入力欄の下に理由を表示します。
- 送信中は対象宛先の入力欄と送信操作がロックされます。もう一方の宛先は操作できます。
- 「入力を消去」は対象カード内で確認します。「編集に戻る」なら本文を残し、「破棄して消去」なら消去します。
- 「次の送信を失敗させる」を有効にすると、次の1回だけ失敗します。失敗時は本文を保持し、「この本文を再試行する」から再送できます。
- ヘッダー、操作概要、各入力欄の「操作ガイド」から同じガイドを開けます。ガイド表示中は背景を操作できず、閉じると開く前のボタンへフォーカスが戻ります。

## 選んだ設計と設計基準との関係

- `App` をRootとして、ヘッダー・操作概要・二つの `MessageComposer`・共通の `HelpDialog` を組み立てています。各 `MessageComposer` は独立した操作領域です。
- 各宛先の入力、送信状態、確認状態、失敗予約、受付回数は `useMessageComposer` の reducer にまとめています。表示部品は値と操作通知を受け取り、送信処理や状態判断はその領域のハンドラが担当します。
- 送信ボタン、フォーム送信、ショートカット、再試行は同じ `requestSend` を通ります。現在状態を確認してから一度だけタイマーを開始し、開始・成功・失敗を reducer へ反映します。
- 確認中は対象領域の入力と送信だけを止め、もう一方の領域は継続できます。確認はカード内に表示し、全画面ダイアログにはしていません。
- 操作ガイドは `role="dialog"`、背景の `inert`、Tab循環、Escape、フォーカスの移動・復帰を実装しています。ユーザー入力はReactのテキストノードとして表示し、HTMLへ直接挿入していません。
- URLやブラウザ保存、外部APIは使わず、仕様に必要な画面内状態だけを保持します。

以上は、提供された `criteria/` のGUI、frontend、Reactのknowledge/policies 6文書を、Root/領域/Mediator、状態の寿命、controlled input、reducerと副作用の分離、標準HTML操作、アクセシビリティ、通信状態表示の観点で適用したものです。文書自体は変更していません。

## 検証したこと

- `npm run build` が成功することを確認。
- TypeScriptの型チェックとViteの本番ビルドを同じコマンドで確認。
- 二つの宛先を別々の状態として扱い、送信中の片方と操作可能なもう片方を分離。
- 空白のみの拒否、約1秒の成功、送信中の重複抑止、1回だけの失敗、失敗後の本文保持、入力消去確認を実装上確認。
