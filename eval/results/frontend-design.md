## 対象と条件

8組の不適切／適切な実装と、フレームワークの自然な実装5例、計21ファイルをレビューした。React facetなしの `frontend-review` と、ありの `frontend-review-react` を同じ課題で実行した。コード、課題、依存パッケージ情報を固定し、期待判定はモデルの作業ディレクトリへコピーしていない。

- Luna: Codex CLI 0.155.1、`gpt-5.6-luna`、reasoning effort `max`、read-only、ユーザー／リポジトリのskill継承を無効化。
- Opus: Claude Code 2.1.277、`claude-opus-5`、`Read,Glob,Grep`、`dontAsk`、project設定。effortの明示指定なし。
- 各条件を新規セッションで1回実行。プロンプト、policy、knowledgeを条件ごとに固定し、キャッシュを使わず既存の `cli-review.mjs` providerを呼んだ。
- 最終版はLunaの回答を確認してからOpusへ進めた。モデル間ではツール設定が異なり、同一モデル内の旧／新比較として扱う。

旧版も全ケースを通過したため、設計判断に関するRED→GREENは観測していない。今回示せたのは、適合例の誤検知と欠陥の検知漏れを、この課題と各1回の試行では生じなかったという回帰確認である。検出能力の改善率や、他の課題に対する一般的な精度は主張しない。

初期採点では、Lunaの正しい言い換えを理由の正規表現が拾えず、OpusのJSONコードブロックも構文エラーになった。語句の許容と単一コードブロックの扱いを修正し、旧／新の保存済み回答すべてへ同じ最終採点を適用した。これは採点処理の修正であり、プロンプトによる設計判断の改善には数えていない。

## 証拠と再実行

[回答原文・入力ハッシュ・モデル設定・採点結果](frontend-design/2026-09-22.json)を保存した。`originalGrading` は各試行時の採点、`finalGrading` は同一の最終採点処理を保存済み回答へ適用した結果である。policyとknowledgeのハッシュは、実際に入力として指定したスナップショットの内容を表す。

比較には同じ21個のTSXと同じ `package.json` を使用した。比較用のpackageには元fixtureのVite/router等も残しているが、コードはそれらを利用しない。通常のsuiteに置いた `frontend-design/package.json` はReact/TanStack Queryだけに整理している。依存インストールやアプリ実行は今回のモデル試行では行っていない。

生成プロンプトと全スナップショット、回答の元ファイルはローカルの `takt-frontend-{baseline,candidate}-{luna,opus}-*` ディレクトリへ保存した。リポジトリには回答とハッシュを保存し、絶対パスを含む生成プロンプト本体は含めていない。中間版のLuna実測も両構成で21件を正しく判定したが、最終版の結果に合算していない。独立レビュー中に入力を変更する必要が生じて停止した2試行は、完了した回答がなく、成功／失敗件数に含めていない。

最新のsuiteを実行する手順は [評価ガイド](../frontend-design.md) に記載している。
