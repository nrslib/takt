Extract completion obligations from explicitly supplied upstream reports and map them to individual implementation and verification evidence in the latest work result. Upstream reports establish obligations and IDs; the work result establishes what was performed. Do not assume a dedicated contract-ledger file or conversation history unavailable during reporting exists.

Output every planned obligation and every obligation newly discovered downstream. Preserve existing IDs, origins, and meanings; do not reassign IDs according to implementation, test, or evidence order. Work results without IDs are sufficient when their concrete evidence clearly maps to upstream obligations. If the inputs define no IDs, use "No ID" for each obligation without inventing IDs or a handoff error.

When prose refers to another contract, use that same ID from the inputs. Before output, check that every input ID remains in the completion table and that table/prose cross-references contain no invented IDs or IDs reassigned to different meanings. Do not omit or merge contract rows merely because one test verifies several obligations.

Make each completion-table row self-contained in its obligation and evidence. Evidence cells must state observations or the reason for non-applicability for that obligation directly, without references to other contract IDs. Without evidence for that obligation, another row's success does not make it Verified. Never omit the final Status cell of any row: select exactly one status supported by that row's evidence.

If the inputs cannot establish an obligation-to-ID mapping or an individual result, set Report Status to "Missing handoff information", retain identifiable rows as "Insufficient information", and identify the missing input. Do not guess unknown rows or evidence; preserve known work results and failures. Missing information alone is not incomplete implementation, an environmental limitation, or a reason to replan. A blanket completion claim or a passing overall test suite alone does not prove individual obligations verified.

When implementation gaps, failed verification, or unexecuted checks are explicitly reported, record those facts and reasons separately from missing handoff information. "Report complete" means the report could be produced, not that implementation is complete.

Select exactly one Report Status instead of reproducing both alternatives. An absent execution record does not prove a check was not run: write "unknown" without inferring non-execution or failure. Use "unknown" also for rows whose defined ID mapping is missing, distinguishing these from "No ID" for plans that define none.
