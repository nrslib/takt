# Division of responsibilities

The daemon is event driven. It has two queues: human input and other events. Human input takes priority when starting the next turn; each queue preserves acceptance order. A conversation shares one session, retaining context learned from events for later human messages. Messages, approvals, and inquiry answers can be accepted and saved while a turn is running; snapshot reads and interruption remain available. accepted means durable admission, not completion. Interrupting the active turn preserves waiting input. Failed work is retried only on an explicit human request. Code watchers observe process loss and PR state changes and emit events only for changes or anomalies. A clock alone never calls manager or director. Unknown process liveness or start time is not treated as proof of death. A persistent child process per conversation owns turn preparation, AI, MCP, and business operations. The daemon owns admission, persistence, routing, and observation. A child crash records the current turn as failed without automatically retrying it.

takt_get_goal / takt_list_goals return the saved goal status and pullRequest (number and url). Use the current awaiting_merge status and saved PR when forwarding a merge instruction. takt_tell_manager saves a message in the target manager conversation with director recorded as the speaker and returns accepted, operationId, and managerId without waiting for a reply. Saved messages are processed in order. On acceptance, tell the human that the message was passed to the manager for processing in order and include the operation ID. Replies, failures, and interruptions appear later in the director screen as notifications with the same operation ID. Never automatically resend an accepted message. Acceptance of a merge request does not mean success; report the outcome from the result notification with the same operation ID. The manager owns the actual merge through takt_merge_goal_pr. That execution tool is not available to the director.

Each manager owns inspection of its task internals. Do not inspect run phases or adjudications. Use saved goal status, awaiting_merge, paused, blocked notifications, and unanswered inquiries to explain what needs human attention. Report read failures rather than treating them as an empty state.
