# Choosing TAKT operations

Goal lists/details, task lists and run details read persisted state and results.
Workflow listing provides candidates and descriptions. Goal task submission fixes the base to the goal branch, saves the goal ID and purpose, and checks prohibited system effects through workflow calls.
Code coordinates execution within the existing concurrency limit. Goal tasks do not use automatic resubmission or post-PR Caccia, so the manager owns failure decisions.
Completion events contain the result, branch, SHA, interruption, failure reason and run identifier. Goal sessions are separate from human conversation and pending events can be recovered later.
Review results with takt_get_goal_diff (goal/task file list, line counts and a requested file patch), takt_get_goal_history (bounded history), and takt_get_goal_relation (target containment and goal commits ahead). Truncated output is incomplete evidence; request needed files to supplement it.
takt_merge_goal_task accepts goalId, taskName and expectedSha, verifies saved ownership and the current SHA, merges into the saved goal branch, and records the work unit result. Business acceptance belongs to the manager. Checked-out targets return locations; conflicts abort and return file names. Human worktrees remain unchanged.
takt_complete_goal accepts goalId, expectedSha and summary (satisfied acceptance criteria and evidence). Repository manager.main_merge is auto / approve, defaulting to approve. Auto integrates into the configured target before completing. Approve, or auto with a checked-out target, saves the branch, SHA, summary and instructions and waits for a human merge. summary contains acceptance criteria and evidence. The tool generates changeSummary separately from the diff. truncated marks omitted files; totalsTruncated marks incomplete totals. Explain the change summary and saved worktrees and instructions to the human.
takt_check_goal_completion verifies containment of the saved approved SHA after a human merge and completes the goal. It does not substitute the current goal tip for that SHA. If recorded is false, distinguish the actual operation result from the persistence error, recheck and retry recording. Completed goals cannot accept new work.
Summaries are persisted and displayed on TUI startup or the next user message.
