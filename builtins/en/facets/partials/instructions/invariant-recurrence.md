**Invariant recurrence:**

- One verifier occurrence is one completed verifier result produced after a fix. Multiple paths reported for one invariant in the same sweep count as one occurrence; a later occurrence counts only when a fix intervenes
- Treat two records as the same observable invariant only when their family ID, invariant stable ID, and authoritative owner match
- Review adjudication must consider only `subworkflows/iteration-N--step-remediation--*/fix-verification.md` directly under the same peer review's Report Directory. Never consider files under `.takt-report-internal`. When multiple candidates exist, select the one with the greatest numeric `N` as the most recent and record every recurrence row and all 13 fields unchanged in the review resolution's Invariant Register Carry-forward. When no remediation directory matches, record No prior remediation. When the greatest `N` does not identify one candidate uniquely, its `fix-verification.md` is unreadable or missing, or its recurrence record is missing, record Carry-forward source missing with the reason and do not fill the gap from an older candidate. For a rename that changes any of the three identity fields, carry values forward only when adjudication explicitly records the old-to-new row mapping and reason: retain the old row as predecessor history and add a new row whose non-identity fields are unchanged. Reappearance under a different ID without that mapping is a plan inconsistency
- A fix plan must not search sibling remediations. When an earlier published fix-verification exists in the same remediation, use its latest recurrence record as the carry-forward source and do not use the review resolution's carry-forward table. If that fix-verification is unreadable or its recurrence record is missing, record Carry-forward source missing with the reason and do not switch to the review resolution. Only when no earlier fix-verification exists in the same remediation may the fix plan use the current review resolution. Copy every invariant row and all 13 fields unchanged from the selected source into the plan before adding new rows. Do not make No prior remediation or Carry-forward source missing and its reason into an invariant row; preserve their distinction through the fix report. Use carried rows only for the established-invariant diff scan and preservation of existing contracts; do not add a carried row outside the families made actionable by the current adjudication to Finding Coverage, Execution Order, or code changes
- When one occurrence reports multiple `participates` paths, record the complete previous and current path sets and compare them as sets. Ordering and duplicates do not affect comparison. For newly establishing the trigger, the current occurrence is a different path only when its set contains at least one path absent from the previous incomplete occurrence's set; removals or shrinkage alone do not qualify
- The recurrence trigger becomes newly true only when that same invariant is `incomplete` in at least two separate occurrences and this added-path condition holds. Increment the cumulative `incomplete` count at most once per invariant per occurrence
- For the same ledger row, evaluate the trigger in this order. First, a carried true trigger remains true even when other recurrence fields are missing or inconsistent. Otherwise, when the record is complete, the trigger is the carried trigger OR the newly established trigger. Once true for matching family ID, invariant stable ID, and authoritative owner, keep it true in every later occurrence, including another failure on the same path; it may return to false only when a change to the family ID, invariant stable ID, authoritative owner, or another explicit plan change is recorded with its reason
- The verifier reads history only from the invariant-register carry-forward in the fix report. The fixer must keep one row for every planned invariant and initialize no occurrence, cumulative count `0`, and trigger `false` only when the carry-forward information is complete and the invariant has no carried row in the fix plan. Keeping and copying every field of a carried row unchanged applies only when review adjudication produces the review resolution, the fix plan copies its register, and the fixer copies it into the fix report. The fix verifier is the only stage that updates the recurrence record for the current occurrence: for each invariant that is `incomplete` in the current sweep, increment the cumulative count once and update the occurrence, paths, recurrence judgment, and trigger under the shared rules. Preserve the recorded occurrences, paths, count, and trigger unchanged only for rows not `incomplete` in the current sweep; preserve an already-true trigger regardless of the current judgment under the existing monotonicity rule. If a later record omits a planned invariant, add its plan identity, preserve any known carried true trigger, mark the remaining recurrence fields indeterminate rather than resetting them, and record the omission separately as a carry-forward deficiency. The verifier must output every planned invariant even when the current sweep does not mark it `incomplete`
- Complete carry-forward information is a prerequisite for treating an invariant as a first occurrence. It is complete only when a register contains every row from the selected source, or when no earlier fix-verification exists in the same remediation and the review resolution explicitly records No prior remediation. With that prerequisite satisfied, classify a first occurrence only when either no row matches the family ID, invariant stable ID, and authoritative owner or the matching row was initialized from the fix plan with no occurrence, cumulative count `0`, and trigger false. Never treat the same invariant as a first occurrence when a carried row exists. When Carry-forward source missing or a reason that prevents unique selection is recorded, copy the reason through the fix plan and fix report, do not convert it to initial values, and continue conservatively as an artifact deficiency. For a complete first occurrence, record the recurrence judgment as `indeterminate (first occurrence)`, keep the trigger false, and allow a normal repair. Preserve a known carried true trigger; otherwise record trigger `indeterminate` and do not choose a repair limited to the reported path. If the same observable invariant reappears with any identity field changed, record the explicit plan change and its reason and retain the old row as predecessor history; without that record, classify a plan inconsistency rather than a first occurrence
- When an invariant is not `incomplete` in the current sweep, preserve its recorded incomplete occurrences, paths, count, and trigger without shifting them; mark only the current judgment as maintained. This preserves the last incomplete path across non-contiguous verifier occurrences
- Mark each missing or inconsistent recurrence field as indeterminate without overriding a carried true trigger. Only when the trigger itself cannot be reconstructed and no carried true trigger is known, record the trigger as `indeterminate`; do not infer `false` or `not recurrent`, and apply the same prohibition as for a true trigger against choosing a repair limited to the reported path. Reconstruct missing artifact fields from the fix-plan register, retain one row per planned invariant, and record the reason as an artifact deficiency; record plan deficiencies under the shared fix-plan-validity rules
