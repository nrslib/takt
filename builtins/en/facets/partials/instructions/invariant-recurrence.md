**Invariant recurrence:**

- One verifier occurrence is one completed verifier result produced after a fix. Multiple paths reported for one invariant in the same sweep count as one occurrence; a later occurrence counts only when a fix intervenes
- Treat two records as the same observable invariant only when their family ID, invariant stable ID, and authoritative owner match. Treat them as different paths when the recorded previous and current `participates` paths differ
- The recurrence trigger becomes newly true only when that same invariant is `incomplete` in at least two separate occurrences and the current path differs from the previous incomplete occurrence. Increment the cumulative `incomplete` count at most once per invariant per occurrence
- For the same ledger row, the trigger is the carried trigger OR the newly established trigger. Once true for matching family ID, invariant stable ID, and authoritative owner, keep it true in every later occurrence, including another failure on the same path; it may return to false only when either an explicit plan change or an invariant stable-ID change is made and the reason for that change is recorded
- The verifier reads history only from the invariant-register carry-forward in the fix report. The fixer must keep one row for every planned invariant: on the initial fix, initialize from the fix plan with no occurrence, cumulative count `0`, and trigger `false`; after verification, copy every existing recurrence-record row from the latest fix-verification unchanged. If a later record omits a planned invariant, add its plan identity with recurrence fields marked indeterminate rather than resetting them, and record the omission separately as a carry-forward deficiency. Only the verifier may set occurrences, increment counts, or decide triggers, and it must output every planned invariant even when the current sweep does not mark it `incomplete`
- If no carried row has a matching family ID and invariant stable ID, or the matching initial row has no verifier occurrence, treat the invariant as a first occurrence. If the same observable invariant reappears under a different stable ID, record a plan inconsistency instead
- When an invariant is not `incomplete` in the current sweep, preserve its recorded incomplete occurrences, paths, count, and trigger without shifting them; mark only the current judgment as maintained. This preserves the last incomplete path across non-contiguous verifier occurrences
- Do not classify missing carry-forward history or an ID mismatch as non-recurrence. Reconstruct missing artifact fields from the fix-plan register, retain one row per planned invariant, and record the reason as an artifact deficiency; record missing or inconsistent plan identity, authoritative owner, or conditionally required enforcement point as a plan deficiency
