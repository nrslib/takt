**Invariant recurrence:**

- One verifier occurrence is one completed verifier result produced after a fix. Multiple paths reported for one invariant in the same sweep count as one occurrence; a later occurrence counts only when a fix intervenes
- Treat two records as the same observable invariant only when their family ID, invariant stable ID, and authoritative owner match
- When one occurrence reports multiple `participates` paths, record the complete previous and current path sets and compare them as sets. Ordering and duplicates do not affect comparison. For newly establishing the trigger, the current occurrence is a different path only when its set contains at least one path absent from the previous incomplete occurrence's set; removals or shrinkage alone do not qualify
- The recurrence trigger becomes newly true only when that same invariant is `incomplete` in at least two separate occurrences and this added-path condition holds. Increment the cumulative `incomplete` count at most once per invariant per occurrence
- For the same ledger row, evaluate the trigger in this order. First, a carried true trigger remains true even when other recurrence fields are missing or inconsistent. Otherwise, when the record is complete, the trigger is the carried trigger OR the newly established trigger. Once true for matching family ID, invariant stable ID, and authoritative owner, keep it true in every later occurrence, including another failure on the same path; it may return to false only when a change to the family ID, invariant stable ID, authoritative owner, or another explicit plan change is recorded with its reason
- The verifier reads history only from the invariant-register carry-forward in the fix report. The fixer must keep one row for every planned invariant: on the initial fix, initialize from the fix plan with no occurrence, cumulative count `0`, and trigger `false`; after verification, copy every existing recurrence-record row from the latest fix-verification unchanged. If a later record omits a planned invariant, add its plan identity, preserve any known carried true trigger, mark the remaining recurrence fields indeterminate rather than resetting them, and record the omission separately as a carry-forward deficiency. Only the verifier may set occurrences, increment counts, or decide triggers, and it must output every planned invariant even when the current sweep does not mark it `incomplete`
- Treat an invariant as a first occurrence only when a complete carry-forward register exists and either no row matches the family ID, invariant stable ID, and authoritative owner, or the matching row was initialized from the fix plan with no occurrence, cumulative count `0`, and trigger false. Record the recurrence judgment as `indeterminate (first occurrence)`, keep the trigger false, and allow a normal repair. If the carry-forward register itself is missing, or evidence such as a prior fix report or verification history shows earlier work but a matching row cannot be reconstructed, do not classify a first occurrence; record an artifact deficiency. Preserve a known carried true trigger; otherwise record trigger `indeterminate` and do not choose a repair limited to the reported path. If the same observable invariant reappears with any identity field changed, record the explicit plan change and its reason and retain the old row as predecessor history; without that record, classify a plan inconsistency rather than a first occurrence
- When an invariant is not `incomplete` in the current sweep, preserve its recorded incomplete occurrences, paths, count, and trigger without shifting them; mark only the current judgment as maintained. This preserves the last incomplete path across non-contiguous verifier occurrences
- Mark each missing or inconsistent recurrence field as indeterminate without overriding a carried true trigger. Only when the trigger itself cannot be reconstructed and no carried true trigger is known, record the trigger as `indeterminate`; do not infer `false` or `not recurrent`, and apply the same prohibition as for a true trigger against choosing a repair limited to the reported path. Reconstruct missing artifact fields from the fix-plan register, retain one row per planned invariant, and record the reason as an artifact deficiency; record plan deficiencies under the shared fix-plan-validity rules
