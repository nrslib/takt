**Only when a shared review adjudication report contains Awaiting external confirmation:**

Read the requirement basis and completion state of necessary in-environment verification for each item in the current adjudication report. Check whether the recorded basis requires that confirmation under the acceptance criteria or existing contracts. Limit this check to the applicability of the basis; do not readjudicate the finding itself. Do not re-examine test or build execution status, results, or logs; judge verification completion only from the adjudication report's record.

Do not treat an item awaiting external confirmation as a REJECT repair target when its requirement basis is recorded, that confirmation is required by the acceptance criteria or existing contracts, and verification for that problem is recorded as complete. If every other requirement is fulfilled, preceding problems are resolved, and only external confirmation remains, select BLOCKED and record each problem's unverified acceptance criterion, requirement basis, where and how to confirm, and evidence needed to decide.

If an item's requirement basis is missing, the recorded basis does not require that confirmation under the acceptance criteria or existing contracts, or the adjudication report records that problem's verification as incomplete, do not treat it as awaiting external confirmation; record the fact that the confirmation remains unverified in the Evidence column of Requirements Fulfillment Check in the final validation report before applying ordinary judgment. The external-confirmation label alone does not exempt unfulfilled requirements or unresolved problems.

For items treated as awaiting external confirmation, copy the repairs and verification completed in this environment and their code state from the adjudication report into the final validation report’s external-confirmation table.
