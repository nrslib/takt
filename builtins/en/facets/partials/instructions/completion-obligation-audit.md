**Completion obligation audit (required before handing work to verification):**

1. Decompose every repair unit in `fix-plan.md` into atomic completion obligations for each applicable invariant and affected path. Treat behavior repair, consumer migration, obsolete-path removal, and preservation of the existing contract as separate obligations, and assign each obligation a unique obligation ID. When `fix-report.md` already contains an obligation from an earlier fix or retry, retain its ID and meaning for the same invariant, path, and type; append IDs only for newly discovered obligations and never renumber or repurpose an existing ID. When the source of truth marks a mechanism, source, or path as forbidden or obsolete for old-path removal, inventory not only callsites but also the production definition, owned state, constructor or setup input, mutator or API, fallback, every consumer, and tests, fixtures, docs, and report evidence as individually applicable finite items. Making the forbidden mechanism unreachable is not sufficient. If the source of truth requires removal, remove the corresponding definition, state, and API, and make the absence of tests depending on the obsolete API or state an individual obligation with evidence. Decide what may remain from source-and-code evidence. For loop, reduce, recursive-traversal, or aggregation invariants, further decompose the obligations into independent control-flow dimensions that are applicable in the source and code: sibling breadth or position (first/middle/last, including a later branch that updates the result), recursive descent through applicable node kinds or wrappers, base or empty cases, accumulator/merge/max across branches, order, and preservation. Do not create a mechanical full cross-product; use only finite dimensions grounded in the implementation structure and contract
2. Before editing, fix the acceptance criterion and the falsification method or observation point that would fail when each obligation is violated. After editing, run the same method against the current code, diff, targeted test, or reproducible result; do not mark an obligation complete from a broad quality-gate pass or a self-report alone. Limit preservation scope to the exact symbols, interfaces, and behaviors explicitly named by the source of truth. Do not expand a preservation obligation merely because something looks public or exported, and do not retain an unspecified legacy API or state as "compatibility" when it conflicts with a forbidden mechanism. Durable regression evidence must verify contract-observable behavior without using obsolete implementation identity or API as a test-operation prerequisite. When the source of truth permits multiple implementations, also confirm that a behaviorally valid alternative is not rejected. Mutations or falsifications should kill a change that violates each obligation, but must not fix the implementation shape to one particular form. Do not treat one falsification or mutant (for example, wrapper counting) as completion of another dimension such as skipping later siblings, resetting the accumulator, or skipping descendants. Require a single-change counterexample or mutant and owned test-failure evidence for each independent dimension; use a separate obligation row when needed. For each assertion in durable regression evidence, map its specificity (error type/category/message, object identity, helper/API name, call count/order, and so on) to an exact element of the source of truth. If the source of truth specifies only reject/throw, assert only that an exception occurs; assert an exact type/category/message only when it is explicitly contracted. Do not fix incidental wording, identity, or structure. When the source of truth or plan explicitly permits equivalent implementations or values, or says an incidental detail is non-contractual, before completion execute at least one temporary behaviorally equivalent substitution that changes only a non-contractual message, identity, or structure, confirm that the owned regression tests pass, and revert the substitution. Record the result as post-edit evidence; an unexecuted self-report is not evidence. Pair mutation/falsification that kills invalid obligations with acceptance of a valid alternative; if either is unverified, the test-evidence obligation is incomplete. Do not generate alternatives indiscriminately for every test; require a finite, applicable substitution only when the source of truth or plan explicitly permits it or the assertion specificity is narrower than the contract
3. Record every obligation as one row in the "Completion Obligations" section of the fix report. Do not collapse obsolete-path removal into one row: split applicable production definition, owned state, constructor or setup input, mutator or API, fallback, consumer, callsite, and tests, fixtures, docs, or report dependencies into atomic obligations, and record post-edit evidence for each. For max, min, or aggregation, include a fixture in which a later sibling different from the first branch determines the terminal result, traverse every applicable sibling, and observe the accumulator being preserved and updated. Exclude this only when the source of truth and code guarantee a single entry and that evidence is recorded. Fill in the pre-edit or returned state, implementation evidence, post-edit evidence, and status; an obligation without evidence is incomplete or a blocker, never complete
4. Before handing work to verification, reconcile that every applicable row is marked "Complete" with post-edit evidence. If any obligation is incomplete, do not report "fix complete"; record it as incomplete or a blocker
