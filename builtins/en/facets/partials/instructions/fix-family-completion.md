**Defect-family completion contract (required):**
1. Before editing, inventory the source of truth, every invariant, entry point, producer, consumer, persistence or reinjection path, side effect, failure path, and migration or removal target for every fix unit. Decompose them into atomic completion obligations in the form `invariant x participating path x counterexample that fails when the invariant is broken`, classify each as `behavior correction / consumer migration / obsolete-path removal / existing-contract preservation`, and assign stable obligation IDs. For hierarchical or composed structures, include direct elements, each sibling path, recursive descendants, and every projection or aggregate deriving the same value as separate participating paths in both completion obligations and counterexamples. Place result-determining elements at different sibling positions so an incomplete implementation that visits only some siblings cannot pass. For order-independent traversal or aggregation, select counterexamples within the source of truth's permitted input domain that vary the number, position, and order of contributing elements, rejecting constant-return implementations, early termination, and traversal of only selected positions. Do not collapse distinct failures, early exits, retries or resumes, or callers into one "tested" item.
2. Independently observe the pre-edit failure for behavior correction, every caller using the new boundary for consumer migration, the absence and non-use of every path the plan classifies for removal, pre-edit observable behavior outside the requested change scope for existing-contract preservation, and the recorded target-and-scope behavior for every support target. Verify each removal and support target separately. Do not restore a path explicitly prohibited or replaced by the source of truth or plan. Map every test assertion to an explicit source-of-truth invariant, an invariant indispensably and directly derived from the source of truth with its source and rationale identified, or a preserved contract, and do not add an assertion when no such mapping exists. When the source of truth specifies only value equivalence, do not fix reference identity or copying behavior in tests. When the source of truth specifies only rejection, do not fix the error type or wording in tests. Do not infer new input classes, behavior, error kinds, wording, or internal representation from defensive implementation and turn them into a test contract when the source of truth does not define them.
3. Fix an independent local issue directly. For a structural issue, treat reviewer locations and counterexamples as discovery starting points, not as the upper bound of completion.
4. Treat every participating path with the same root cause as one fix unit. Migrate every consumer to the new boundary and remove replaced duplicates and every obsolete path the plan classifies for removal. Close correct operation of the new path, migration of every consumer, absence of each removal target, and every contract the plan classifies for preservation separately.
5. Implement fix units in dependency order. After each unit, rerun every obligation in that unit and any already-completed obligation affected by the change. Do not repeatedly run expected failures for units that are not implemented yet; verify the whole plan in the final completion sweep. A broad test-suite pass is a quality gate, not evidence for an obligation whose counterexample was not observed.
6. Add an undocumented condition with the same root cause to the current fix unit's completion obligations and fix it now when it does not change the remediation assumptions. When the root cause, target responsibility or source of truth, or task-level design changes, request revision of the remediation approach or plan available to this step.
7. After implementation, perform a completion sweep separate from editing. Classify every completion obligation as `complete / not applicable / incomplete` and record evidence. Do not declare completion while any obligation is unverified, any obsolete path remains, or any search result is unexplained.
8. Recheck changed locations and their direct impact paths, and fix newly found independent local issues.
