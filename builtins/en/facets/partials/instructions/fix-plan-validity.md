**Fix plan validity:**
- Preserve each finding's problem, evidence, and acceptance criteria. Treat reviewer-proposed remediation methods as candidates, not as the source of truth
- When an issue belongs to a contract family recorded by the authoritative source, bound the remediation by that family's completion obligations and every existing path with the same responsibility—including production, validation, persistence, restoration, normalization, and output—not by the latest reported location. Do not split violations of the same invariant into separate location-by-location repairs
- Reconcile remediation methods, verification methods, and completion criteria with the requirements, current code, active Policy / Knowledge, and public contracts. Make completion externally observable; lock internal representation or natural-language structure only when it is itself a public contract
- Behavioral verification must traverse the target contract path and observe a point that fails when an invariant is broken. Static invariants may instead be verified through appropriate static analysis or code inspection
- Classify whether each item of evidence can be obtained in the current execution environment. Separate evidence from completion criteria only when it meets every condition in the active Policy for items that cannot be demonstrated due to environmental factors. Verify the implementation through deterministic alternative tests, static inspection, and execution-path or CI wiring before recording follow-up verification
