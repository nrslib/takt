When writing findings, reports, or summaries, follow these rules.

- Use generally understood technical terms.
- Do not invent coined labels, metaphorical labels, or abbreviations.
- Do not carry session-specific shorthand or compressed terms into a report.
- Use only status and classification labels already defined by the output contract or policy.
- Examples of existing vocabulary include `new`, `persists`, `resolved`, `false_positive`, `overreach`, `out_of_scope`, and `no_issue_after_verification`.
- For an open-vocabulary tag such as `family_tag`, you may create a new value for a new problem family.
- Name open-vocabulary tags with combinations of generally understood technical terms; do not use coined words, metaphors, or session-specific abbreviations.
- Use defined labels exactly as written without renaming them.
- Unless the output contract or policy requires a label, explain the point in plain technical language instead of creating a new label.
