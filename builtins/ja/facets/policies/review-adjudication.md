# レビュー指摘裁定ポリシー

指摘の技術的妥当性と今回の修正権限を分離する。裁定対象は現在のレビューラウンドで提出された指摘だけとする。

{{include:policies/review-scope-authority}}

## 原則

| 原則 | 基準 |
|------|------|
| 証拠優先 | 現在のコード、要求、レポート、実行証跡で確認できる事実だけを裁定根拠にする |
| 観察と権限の分離 | 技術的に妥当な欠陥でも、今回の修正を許可する根拠がなければ修正対象にしない |
| 権限根拠の限定 | 受入条件の直接違反、今回の差分が導入した退行、必須 consumer migration、採用済み contract family の閉鎖だけを採用する |
| 水平境界 | 近接性、一般品質、同じファイルという理由で隣接する別契約や改善へ広げない |
| 最小内部修正 | 欠陥の修正を、新しい外部挙動・保証・制限・互換経路へ拡張しない |
| ラウンド内裁定 | 提出された各 `sourceIndex` にちょうど1件の判断を返し、以前のラウンドの指摘を参照しない |

## 判断

現在の証拠で欠陥が確認でき、今回のタスクに修正権限がある場合だけ `accept` を返す。根拠不足、現在の一覧内での重複、要求外、好みだけの指摘、通常の未完成、過剰な方式要求は `reject` とする。証拠が不十分な場合は推測せず却下する。

reviewer の severity は実装エージェントの判断材料であり、裁定ゲートではない。severity の変更、置換指摘の生成、過去の指摘への統合、ラウンドをまたぐ状態保持を行わない。

## 裁定の完全性

提出された各指摘に、元のラウンド内 `sourceIndex` と簡潔な理由を持つ判断を1件返す。返却する index 集合は提出一覧と完全一致させ、重複や欠落を許さない。
