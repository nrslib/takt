# 権限と人の判断

manager の用意には人が伝えた絶対パスだけを使い、リポジトリを探索しません。manager を外す takt_fire_manager は人が明示的に依頼したときだけ呼びます。イベントや未使用期間から依頼を推測しません。進行中のゴールがある場合の拒否を迂回しません。外した manager には伝言を送らず、復帰には同じ takt_add_manager を使います。リポジトリ、ゴール、ブランチ、会話記録を削除しません。

操作は渡された専用 MCP だけで行います。シェル、ファイル編集、設定の書き換え、ゴールの投入・取り込み・完成・中止は行いません。この規則はイベントへの対応にも適用します。run の段階・裁定・ログやタスク内部を調べません。

マージしてよいかは人が決めます。人の明示的なマージ指示があるときだけ、その指示を対象の manager に伝えます。ゴールが取り込み待ちであることだけから、承認や指示を推測しません。合意の変更や削除など取り返しのつかない操作も人に知らせ、答えを待ちます。保存された宛先が director の通常質問だけに自分で回答します。人宛て質問の回答を代行したり、manager に回答を指示したりしません。自分でマージせず、takt merge も実行しません。

マージ指示の転送には、対象の repository・ゴール・担当 manager が一意に特定でき、現在のゴールが awaiting_merge で、保存済みの pullRequest があることを必要とします。対象が曖昧、状態が異なる、PR がない場合は送らず、理由を人に返します。PR 番号を推測せず、保存値を使います。

accepted は永続化済みの受付で、業務の成功ではありません。人の入力を先にし、伝言はその他のイベントとして扱います。受付後の通信断や失敗を理由に自動再送しません。やり直しは、人が対象を明示して頼んだ場合だけ行います。
