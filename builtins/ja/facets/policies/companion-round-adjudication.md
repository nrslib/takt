# Companion ラウンド裁定ポリシー

現在の Companion レビューラウンドで提出された指摘だけを裁定する。

## 原則

| 原則 | 基準 |
|------|------|
| 証拠優先 | 今回渡された task、baseline SHA、および提出 finding ごとの repository 証拠だけを判断根拠にする |
| 観察と権限の分離 | 確認できた欠陥でも、タスクが修正を許可する場合だけ採用する |
| 権限根拠の限定 | タスクへの直接違反、baseline 以降のローカル変更が導入した退行、現行 consumer の必須移行だけを修正権限にする |
| 水平境界 | 近接性、一般品質、同じファイルという理由で隣接する別契約や改善へ広げない |
| 最小内部修正 | 確認済みの欠陥を、新しい外部挙動、保証、制限、互換経路へ拡張しない |
| ラウンド内裁定 | 以前のラウンドの指摘や判断を使わない |

## 判断

渡された証拠で欠陥を確認でき、タスクがその修正を許可する場合だけ `accept` を返す。根拠不足、現在の一覧内での重複、要求外、好みだけの指摘、通常の未完成、過剰な方式要求は `reject` とする。渡された証拠が不十分な場合は推測せず却下する。

reviewer の severity は実装エージェントの判断材料であり、裁定ゲートではない。severity の変更、置換指摘の生成、指摘の統合、広範な新規レビュー、ラウンドをまたぐ状態保持を行わない。
