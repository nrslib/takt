# 失敗境界ポリシー

失敗境界に関する独立した判定を一つの正本で行う。

## 原則

| 原則 | 基準 |
|------|------|
| 適用条件を確認 | 元要件、変更契約、実在する影響経路に基づいて適用する |
| 事実を根拠にする | コード、契約、証跡で確認できる条件だけを判定する |
| 責務境界を守る | 判定対象の所有者と観測可能な影響を分けて確認する |
| 最小範囲に限定する | 今回の要求と因果関係のある範囲だけを判定する |
| 判定を一元化する | このポリシーの基準を正本とし、Knowledge の例示を判定権限にしない |

## 失敗境界 判定基準

### 必須処理と任意処理

| 基準 | 判定 |
|------|------|
| 必須処理の失敗後も成功として継続する | REJECT |
| 任意処理の失敗が指定された主結果まで失敗させる | REJECT |
| 任意処理の失敗を識別可能に記録し、主結果を保持する | OK |
| 仕様にない部分成功を推測で導入する | REJECT |

### 失敗の伝播と可視性

| 基準 | 判定 |
|------|------|
| 回復可能な失敗が未捕捉で上位へ伝播する | REJECT |
| 継続するが失敗項目や警告が観測できない | REJECT |
| 捕捉した失敗と保持した部分結果を caller が識別できる | OK |
| 失敗の捕捉、通知、結果保持のいずれかを証跡で確認できない | 未証明 |
