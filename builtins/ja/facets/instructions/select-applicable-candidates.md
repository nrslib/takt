渡された変更ファイルのパス一覧と Report Directory・レポート名の参照を根拠にする。まず実装報告、計画、最新の review-resolution.md を読み、レポートから境界を判定できない場合に限って変更ファイル本体を読む。selector は読み取り専用で実行され、ファイルの変更・書き込みはできない。ツール許可リストを尊重する provider では `Read`・`Glob`・`Grep` のみが許可される。判定に必要なファイルとレポートは利用可能な read-only tool で読み、ファイル名だけで判定しない。対象エージェントのプロンプトが提供されている場合は、それも根拠にする。各入力を制御する主体、入力が越える信頼または権限の境界、入力が到達する処理や資産を判定する。候補は description の条件に該当する場合だけ選び、該当する候補はすべて選ぶ。最新の review-resolution.md に候補が提出した未解消の actionable finding が残っている場合は、その候補の description が該当しなくても選び続ける。follow-up のレポートがその finding を解消済み、統合済み、または対象外として明示的に記録するまで続ける。どの候補にも該当しなければ selected_ids を空配列にし、既定では選ばない。
