Report Directory にある各専門レビュアーのレポートを検証し、未判断の指摘と担当観点内の見落としを証拠で裁定して、今回修正してよい対象を確定してください。

{{include:instructions/review-adjudication-check}}

新しい専門観点を追加せず、Report Directory 配下で現在参照できる各レビューレポートを提出元として扱ってください。以前のラウンドで判断済みの指摘は既存の裁定から引き継ぎ、現在のレポートにある未判断の指摘と、提出元の担当観点内で確認できる見落としだけを新たに裁定してください。必要な範囲で現在のコード、要求、計画、実行証跡を確認してください。

各指摘について、技術的な主張、具体的な失敗条件、証拠、今回修正が必要な理由を分けて確認してください。採用する修正対象には、その理由、破られている観測可能な条件、関係する契約経路、受入条件、修正境界を記録してください。

既存の裁定結果と履歴は、判断済みの指摘を再裁定せず、同じ原因、破られる条件、受入条件を持つ問題を照合するために使ってください。修正履歴や完了検証だけを指摘の提出元にせず、レビューレポートに提出された未判断の指摘を裁定してください。

指摘の新規裁定とは別に、計画レポートの「留意点」（通常計画では「確認事項（あれば）」に記録された持ち越し事項）は既知事項として読む。対象は、レビュアーが指摘として提出した項目と、レビューレポートの「非finding化した懸念」（testing-review では「未確認範囲」）に「計画の留意点として持ち越し」として記録された項目の両方である。未提出の項目も含め、各項目を「今回の修正対象にする／持ち越す／却下する」のいずれかに根拠付きで裁定してください。レビュアーが新規指摘として再提出しても、既知事項の再評価として扱い、判断済みの指摘の裁定は以下の `reopened` 条件を満たさない限り維持してください。

判断済みの指摘を再裁定する例外には、次の共通定義を適用してください。

{{include:output-contracts/base-review-reopened}}

各指摘と、検証で確認した見落としの裁定、および同じ原因を持つ問題の統合先を漏れなく記録してください。結果はレビュアーの票数ではなく、現在の証拠と裁定基準に基づいて決めてください。裁定できない懸念は推測で除外せず、未解決の前提として明示してください。
