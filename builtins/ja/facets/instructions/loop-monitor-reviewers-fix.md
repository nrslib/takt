レビュー → 修正のループが {cycle_count} 回繰り返されました。

Report Directory 内の最新レビュー報告と修正報告を調べ、このループが健全（収束中）か、非生産的（発散・振動・停滞）かを判断してください。

**最初に観測時点を確定してください:**
- 最新の修正後に fix-verifier またはレビューが実行済みか、Report Directory の時系列で確認してください。最新報告が fix-verification.md なら、`incomplete` の理由、未充足の検証義務、再試行で変わった証拠を比較し、同じ理由と証拠のまま反復していれば停滞とします。最新報告が review-resolution.md または別のレビューレポートなら、代わりに finding ID、裁定、受入条件、現在の証拠を比較してください。
- 修正完了直後で verifier も修正後レビューもまだない場合、直近の fix-report.md で当該修正単位の「完了義務」がすべて「完了」または「該当なし」で閉じられ、「未完了義務」がないと記録されている場合だけ「修正後の検証待ち」とし、健全・進捗ありの条件に含めてください。修正したとの記載があっても完了していない義務が残る場合は、修正未完了として扱ってください。
- 当該指摘を修正したとの報告がない場合は、後続の検証報告がないことだけで健全と判断しないでください。

**判断基準:**
- **修正進捗:** 前回の open findings の受入条件が満たされたかを、修正報告、現行コード、修正後レビューで確認してください。同じ `finding_id`、根本原因、または受入条件が修正後も繰り返される場合は、実装が未完了です。
- **報告の収束:** 完了したレビュー回を比較し、正しい構造・契約上の new findings が追加され続けていないか確認してください。以前の指摘が解消していても、この状態はレビュー報告が未収束です。
- 監視対象 cycle に未充足の完了義務が残っている間は、健全（収束済み側）の選択肢を選ばないでください。進捗があり、次の修正が実行可能なら、修正未完了だが実行可能な側を選んでください。
- 記録済みの再発履歴だけを監視してください。「別経路での再発が確認済みか」が「確認済み」の場合、毎回異なる経路が修正されていることを健全・進捗ありの根拠にしないでください。
- 履歴の不足・不整合、または「別経路での再発が確認済みか」を復元できず「判定できない」と記録された行は、非再発ではなく成果物不足として扱い、「確認済み」と同じ慎重な扱いをしてください。完全な「判定できない（初回）」行は別経路での再発が「未確認」の通常結果として扱ってください。成果物不足では fix-verifier が完全な台帳を再構築するまで健全・進捗ありを選ばず、利用可能な検証または立て直しの選択肢を使ってください。成果物不足だけを再計画の根拠にしないでください。
- 計画に不変条件、担当箇所（この不変条件を定め、成立を保証する単一の責務・参照元）、該当する強制義務が既に記録されている場合、その実装漏れまたは実装不足は `incomplete` のままです。物理的なコード位置やファイルパスを同一性の根拠にせず、ファイルの移動・分割だけで別の不変条件として扱わないでください。再計画ではなく構造修正の継続を選んでください。
- 再計画側の選択肢を選ぶのは、計画の必須項目、前提、修正境界、方法、証拠能力が不足・不整合で、計画変更によって解消できる証拠がある場合だけです。再発だけを計画前提の不足の根拠にしないでください。
- 異なる `family_tag` の new finding であること自体は、健全とも非生産的とも判定する根拠になりません。内容、影響範囲、発見されたレビュー回を確認してください。
- 新規指摘が有限な局所問題に限られ、構造・契約上の未確認領域が増えていない場合は収束中と判断できます。
- 修正報告の修正単位と受入条件の証拠を現行コードへ照合し、対象 finding が実際に閉じているか確認してください。
- 修正後レビューの指摘が現行コードと乖離している場合は、同一修正を繰り返さず、利用可能な再確認・立て直し・停止の選択肢から判断してください。
- 件数は補助情報に留め、修正進捗と報告内容の収束を別々に判定してください。

直前に完了した review ラウンドの最新 reviewer reports が全件 `APPROVE` で、`new`、`persists`、`reopened` がない一方、同じ actionable family がその reviewer reports にはなく、Report Directory に現在存在する `review-resolution.md` にだけ記録され、修正の再実行に対する `fix-verification.md` がその family を対象に含み、結果を `verified` と記録している場合は、次のレビュー・修正で解消できる通常の停滞として扱わないでください。別のレビューまたは同じ修正の再実行では解消できない場合に対応する、現在の loop monitor に宣言済みの選択肢を選んでください。reviewers または同じ fix を直接再実行する選択肢は選ばないでください。

実装未完了または報告未収束のいずれかで、かつ利用可能な打開手段がない場合、または上記の resolution だけによる反復がある場合に限り、同じレビュー・修正を再実行しない選択肢を選んでください。この反復について reviewers または同じ fix を直接再実行してはいけません。
