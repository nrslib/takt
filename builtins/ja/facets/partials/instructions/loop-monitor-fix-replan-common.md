**判断順序:**
1. fresh な triggering response が blocker を特定し、それに対する新しい分解、別の実装方針、または検証可能な受入条件を裏付けているか確認してください。
2. 現在の要件と受入条件を変えずに、実装方針・テスト方針・指摘の扱いを再定義できるなら replan を選んでください。
3. triggering response が従来の方針の反復や同じ原因の指摘の再発を示していても、具体的な別案があるなら replan を選んでください。
4. 試行済みの方針を踏まえても、要件を満たす実現可能な方針が存在しない場合に限り ABORT を選んでください。

ABORT の場合は、live state と triggering response から、成立しない要件上の制約と試行済みの方針を簡潔に示してください。
