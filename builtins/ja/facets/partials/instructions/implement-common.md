**重要**:
- ビルド確認は必須。実装完了後、ビルド（型チェック）を実行し、型エラーがないことを確認
- テスト実行は必須。ビルド成功後、必ずテストを実行して結果を確認
- ファイル名・設定キー名などの契約文字列を新規導入する場合は、定数として1箇所で定義すること
- 計画と既存テストは最低限の完了義務であり、実装全体の完成を証明するものではない。各契約IDに実装箇所と直接の検証証拠を対応させること
- 影響経路を持つ契約では、同種分岐、補助入口、消費元を実コードから再走査し、移行した経路、保持した経路、除去した旧経路を確認すること
- 契約の影響経路に連続実行、再進入、並行交差、失敗終端が実在する場合だけ、関係するシナリオを、その契約を観測できる適切な入口から確認すること
- 広いテストスイートの成功、テストファイル名、静的な読み合わせだけを、個別契約の確認済み根拠にしないこと
- 環境要因で実証できない項目は、実行可能な決定的代替検証と残る未確認範囲を分けて記録する。同じ環境で証拠を増やせないことだけを理由に実装欠陥と扱わない

**実装完了前の自己チェック（必須）:**
ビルドとテストを実行する前に、次の手順で Policy の REJECT 基準を自己点検してください。
1. Policy の Source Path を Read ツールで開き、全文を取得する
2. 各 `##` セクションをすべて列挙する（取捨選択しない）
3. 列挙した各セクションの REJECT 基準と自分の実装を照合する
4. 各契約IDの反例を現在の実装へ適用し、契約を直接観測できる入口から期待する振る舞いを確認する
5. 高リスク契約について証拠がなく、現在の作業範囲で追加検証できる場合は実装完了を選ばない
