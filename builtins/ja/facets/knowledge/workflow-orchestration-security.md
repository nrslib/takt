# ワークフローオーケストレーションのセキュリティ知識

## 適用条件

宣言的なワークフローが実行対象、実行主体、状態、権限、または動的選択を解決・引き継ぐ経路を変更する場合に適用する。ワークフローの文言や表示だけを変え、実行経路と信頼境界を変えない変更には適用しない。

レビューでは、低信頼の入力、変更対象となる実行能力、両者を結ぶ具体的な経路を示す。設定項目や実行機構が存在するだけでは脆弱性と判定しない。

## 宣言と実行の一致

schema、loader、normalizer、検証・表示経路、runtimeは同じ設定契約を解釈する必要がある。境界で解決した値を後段が別の優先順位で再解決すると、検証された内容と実行される権限や実行主体が乖離する。

| 基準 | 判定 |
|------|------|
| 検証・表示された値とruntimeの解決結果が異なり、実行能力が広がる | REJECT |
| 未知参照や不正な選択結果を、より広い既定値へ黙って置換する | REJECT |
| 文書化された優先順位に従い、同じ信頼レベル内で定義を上書きする | OK |
| 境界で一度解決した値を実行・表示・保存で共有する | OK |

## 実行主体と状態の所有権

provider、session、resume snapshot、retry、並列実行単位などの識別情報は、所有者が一意になるキーと保存境界を持つ必要がある。

| 基準 | 判定 |
|------|------|
| 異なる実行主体や並列実行単位のsessionを再利用できる | REJECT |
| snapshotが異なるstep、親実行、または入力へ適用される | REJECT |
| retry後の新しい実行が古い識別情報を暗黙に継続する | REJECT |
| 所有者を含む識別キーと状態の保存・読込境界が一致する | OK |

## capabilityの保持

呼び出し元が宣言したtool、編集可否、filesystem、networkなどのcapabilityは、子ワークフロー、provider、tool実行まで保持する。子が必要とする権限は明示的な契約にし、暗黙に拡張しない。

| 基準 | 判定 |
|------|------|
| 宣言されたreadonly境界を越えて編集や外部副作用へ到達できる | REJECT |
| 子ワークフローが呼び出し元より広いcapabilityを暗黙に得る | REJECT |
| 低信頼の設定が、呼び出し元の許可を越えて実行toolやsandbox境界を広げられる | REJECT |
| 宣言したcapabilityが末端の実行まで狭めたまま保持される | OK |

## 外部定義の取込

外部package、workflow、facet、pluginなどを実行可能な定義として取り込む場合は、取得した内容の同一性、取込root、実行時に得るcapabilityを同じ境界で確定する。remote由来であること自体や、文書化された優先順位で定義を選べること自体は脆弱性ではない。

| 基準 | 判定 |
|------|------|
| 記録した不変のsource identityと、検証・実行する内容が一致しない | REJECT |
| 取込内容が許可rootを越える、または低信頼側から高信頼の定義をshadowできる | REJECT |
| 取込時に示した範囲を越えるcapabilityを、実行時に暗黙に得る | REJECT |
| 同じ内容を検証・保存し、source identityとcapabilityを後の実行境界まで保持する | OK |

## 選択・並列実行・失敗

動的selectorや並列実行は、決定が確定する前に副作用を開始しない。選択失敗を「全候補」「強い既定値」「別の実行主体」へ読み替えない。

| 基準 | 判定 |
|------|------|
| selector失敗時に全候補または権限の広い候補を適用する | REJECT |
| 一部の準備失敗後に兄弟実行が副作用を開始する | REJECT |
| provider失敗を異なる信頼境界のproviderへ暗黙に切り替える | REJECT |
| すべての入力と選択を確定してから実行を開始し、同じ所有境界で失敗する | OK |
