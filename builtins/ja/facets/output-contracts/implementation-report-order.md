入力に明示された上流レポートから完了義務を取り出し、最新の実装作業結果にある個別の実装・検証証拠と対応付けてください。上流レポートは義務とIDの根拠、作業結果は実施結果の根拠です。専用の契約台帳ファイルや、報告時に参照できない会話履歴の存在を前提にしないでください。

計画の全義務と、後段で新規発見された義務を全件出力してください。既存のID、由来、意味を維持し、実装順、テスト順、証拠順に合わせてIDを付け替えないでください。作業結果にIDがなくても、上流の義務と具体的な証拠の対応が明確なら報告できます。入力がIDを定義していない場合は「IDなし」として義務ごとに記載し、新しいIDや引き継ぎエラーを作らないでください。

本文から別の契約を参照する場合も、入力にある同じIDを使ってください。出力前に、入力の全IDが完了契約表に残っていることと、表・本文の相互参照に入力にないIDや別の意味へ付け替えたIDがないことを照合してください。複数の義務を同じテストが検証していても、契約行を省略・統合しないでください。

完了契約表の各行は、その行の義務と証拠だけで読めるようにしてください。証拠欄では別の契約IDを参照せず、その義務に対する観測値または非該当の理由を直接記載してください。その義務に対する証拠がないまま、別の行の成功だけで確認済みにしないでください。各行の最後の「状態」列を省略せず、証拠に対応する状態を必ず1つ記載してください。

義務・IDの対応または個別の結果を入力から確定できない場合は、報告状態を「引き継ぎ情報不足」とし、特定できる行は状態を「情報不足」として残し、不足している入力を記載してください。不明な行や証拠は推測せず、判明している実施結果・失敗は保持してください。情報不足だけを実装未完了・環境要因で未実証・再計画が必要な理由に変換しないでください。一括の完了自己申告や全体テストの成功だけでは個別義務の確認済みを証明できません。

実装の欠落、検証失敗、未実行が具体的に報告されている場合は、その事実と理由を記録してください。これは引き継ぎ情報不足とは別です。「作成完了」は報告を作成できた意味であり、実装完了を意味しません。

報告状態は選択肢を併記せず、いずれか1つを選んでください。入力に実行記録がないことは「未実行」の証拠ではありません。その場合は「不明」と記載し、未実行・失敗を推測しないでください。定義済みIDの対応が欠落している行も「不明」とし、IDを定義しない計画の「IDなし」と区別してください。
