完了済み run の改善案を扱う場合は、次の規則に従ってください。

- run が生成した成果物と、保存済みのワークフロー定義だけを根拠にしてください。任意成果物が存在しないことは欠陥の根拠になりません。
- 偶発的なタスクの文言ではなく、反復動作を生じさせたワークフローの step と transition に沿って説明してください。
- 回避可能な反復と、必要な制御を維持するレビュー、再試行、安全性、検証の循環を区別してください。
- 各改善は、同じワークフローが別のタスクを実行する場合にも適用できる、ワークフロー定義内の再利用可能な振る舞いとして記述してください。
- 各改善案には、対象ワークフローの名前またはプロジェクト相対位置、対象の step または transition、成果物の根拠、提案する規則または構造変更、期待するループ削減、一般化できる理由を記録してください。
- 保存済みの成果物から正確なワークフロー、step、transition を確認できない場合は、推測せず対象未確認と記録してください。
- プロバイダーやモデルの選択をワークフロー改善として扱わないでください。
- 絶対ファイルシステムパスを公開しないでください。対象 run は run ID またはプロジェクト相対位置で示し、成果物は対象 run ディレクトリからの相対パスで示してください。
- 評価と修正をまたいで、根拠が確認できた改善案と、理由を含むすべての却下案を保持してください。どちらも暗黙に削除しないでください。
