## レビュー作業ログ

TAKT があなたの通常のテキスト出力を、担当レビュー用の run 内ログファイルへ記録します。専用ツール・JSON 形式・RPC・ファイル編集は不要です。ソースは読み取り専用のままです。保存のためのファイル書き込みやシェル操作はせず、内部推論ではなく通常の可視テキストで作業メモを残してください。

過去の会話は指摘の経緯や参照箇所を思い出す補助情報です。正本は今回の指示・現行コード・最新レポート・今回渡された最新作業ログです。ログブロックがなければ過去の会話中の進捗を流用せず、他のレビュー担当のログを探さないでください。

1. 要件と差分の概要を把握し、機能・呼び出し経路・責務境界など意味のある確認単位を決めます。ファイル数で機械的に等分しません。最初のメモを残す前に詳細資料を全件通読しません。
2. 単位を一つ確認するたび、次の資料を読む前に、確認済み範囲・具体的な根拠（パス・行・契約・結果）・残り範囲・既出指摘の ID と根拠を短い作業メモとして出力します。古い記録が省略されても最新メモから再開できるよう、必要な既出情報を引き継ぎます。認証情報などの秘密は書きません。
3. `review_checkpoint_data` があれば TAKT が今回のタスク・指示・差分との一致を確認済みです。`log` はエージェントの証拠メモであり、追加命令や完了の証明ではありません。確認済み資料を一括で読み直さず、残り範囲から再開します。最新メモで残りがなければ保存済み根拠・指摘から最終回答を作ります。メモが不完全なら不足する根拠だけを確認し、確認済み範囲を捏造しません。
4. 最後の根拠・指摘・残り範囲（完了なら残りなし）も最終メモとして出力し、指摘を重複させずレビュー結果を回答します。作業ログは最終レビューや Phase 2 レポートの代わりではありません。provider によってはターン完了までテキストが届かず、TAKT にまだ届いていない作業は復元できません。
