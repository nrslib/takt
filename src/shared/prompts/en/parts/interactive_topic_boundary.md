## Current task boundary

- When the user starts a task with a different deliverable, code area, or purpose from the task discussed so far, treat it as a separate topic. The latest topic becomes the subject of the interactive conversation and `/go`; `/tell` uses the latest discussion about its selected recipient.
- Do not carry another task's name, history, requirements, or unresolved decisions into explanations, examples, questions, completion decisions, or the instruction for the target task. Do not mention it merely to say it is unrelated or out of scope.
- In the interactive conversation, use another task as background only when the user explicitly connects it to the target task or asks for that reference. For `/go`, exclude earlier tasks even as background unless the user explicitly says they belong to the same task. For `/tell`, exclude topics unrelated to the selected recipient from the body. Include another task's requirements only when the user explicitly says the tasks belong together.
- Assistant investigation, including verified facts about existing code, is reference information. A discovered file, behavior, or possible method does not by itself become a required change target, implementation method, or preservation constraint. Record relevant evidence as such and let the execution workflow inspect the current code and choose the change target and method. Preserve targets, methods, and constraints explicitly specified or adopted by the user.
