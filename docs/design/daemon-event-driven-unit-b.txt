作ったもの

・src/infra/daemon/eventStore.ts、eventRecord.ts
  FileEventStore は EventStore を実装する。eventId または conversationId/requestId で重複を照合する。
  queued → running → settling → settled を一時ファイル・rename で保存する。
  同一ターンの開始・結果・settled 更新は冪等。異なる世代・内容の結果は拒否する。
  settled も重複照合と最終受付連番のために残し、restore.pending は未終了分だけを非同期に列挙する。
  running を中断として扱う判断と、settling の結果だけを再反映する判断は既存 dispatcher が行う。
  発言ごとの agentOverrides を全体として保存・復元・重複応答する。
  名前変更後に応答だけ失敗した保存も、再送で照合できる。
  既存 Goal の問い合わせで kind が省略された結果も、schema の正規化を揃えて再送・確定できる。

・src/infra/daemon/conversationStateStore.ts
  ConversationStateStore.read/create/save/apply を提供する。
  既存 conversations/<id>.json を読み、daemonState がなければ保存版 0 として扱う。
  元の会話レコードと daemonState（版、ターン、操作 ID、変更内容、保存済み版）を同じファイルに保存する。
  同じ操作の再送は版照合より先に同じ結果を返す。別内容・別ターンでの操作 ID 再利用は拒否する。
  同じ期待版で競合した保存は一方だけ成功する。
  session・提案・承認と現在の assignment の整合は ConversationRecordSchema で検証する。
  取消を公開前に確認し、一時ファイルとロックの後始末が済むまで返信しない。
  apply は interrupted.change も反映でき、同じ結果の再反映で版を増やさない。

・src/infra/daemon/privateFile.ts、lock.ts、io.ts
  ファイル I/O は fs/promises。サイズを制限した記述子からの読取、同じディレクトリの一時ファイル、0600、rename、ファイルと親ディレクトリの同期を行う。
  作成ディレクトリは 0700。Windows では POSIX のディレクトリ chmod/fsync を適用しない。
  FileAsyncLock は AsyncLock を実装する。取得は排他的な wx、待機は取消可能な非同期処理。
  処理の Promise と解放の完了まで保持し、両方の失敗は AggregateError にする。
  期限を過ぎた実行中の処理も早期解放せず、処理・解放後に期限切れを返す。
  死亡を確認できた旧所有者だけを回収し、unknown は死亡としない。

・src/infra/daemon/command.ts、process.ts
  AsyncCommand: shell:false、引数配列、期限・取消、stdout/stderr 合計のバイト上限、超過時の停止、終了確認。
  AsyncProcess: 起動後に OS の開始時刻を取得。取得不能なら終了を確認して起動を失敗にする。
  launch の期限は起動確認まで、signal は返したプロセスの寿命にも適用する。
  launch の標準出力・標準エラーは破棄する。出力が必要な短い照会は AsyncCommand.run を使う。
  Linux /proc、Darwin ps、Windows PowerShell を非同期で照会し、alive/dead/unknown を区別する。
  既存の linux-start-v3、darwin-start-v2、Windows 時刻、tasks.yaml の ps 表示形式を扱う。

・owner.ts、ipcEndpoint.ts、infra/slack/inquiryBindings.ts
  owner・接続情報・Slack 問い合わせの既存保存形式を維持し、読書きと所有権処理を非同期化した。
  Slack の競合する保存もロックで直列化する。
  resolveDaemonConfigDirectory は設定ディレクトリを引数で受け取り、非同期で canonical path にする。
  設定解決の同期モジュールは daemon 側に import しない。

・src/infra/daemon/logger.ts、persistedFiles.ts
  DaemonLogger は小さいログレコードを daemon-logs/*.json に原子的に保存する。
  1 メッセージ 16 KiB、同時書込 32 件。close は未終了書込と失敗を確認する。
  DaemonPersistedFiles は既存 .takt/goals/<id>/goal.json、.takt/tasks.yaml、manager-inbox/<project-hash>/*.json を非同期に読む。
  goals/tasks/inbox の読取は各 256 KiB 以下に制限し、全件解析を追加していない。
  tasks は保存形式を検証して全フィールドを保持する。業務 schema の値 import は同期 run 読取を呼び込むため使わない。
  EventStore と会話ファイルは各 4 MiB の上限を設けた。上限を超えたファイルは黙って省略せず失敗する。

・src/shared/utils/executable-path-async.ts と spawn.ts
  spawn の System32 解決を fs/promises に変更し、同期 executable-path.ts への値依存を除去した。
  taskkill 自身にも出力上限と期限を設け、close を待つ。
  ManagedProcess.wait は spawn error の場合も close を確認してから reject する。
  同期の実行ファイル解決は CLI・ターンの既存利用側のために独立した実装として残している。
