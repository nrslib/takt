## 変更する引き継ぎ

- `development-implement` の固定・動的・team 各版は、実行可能な必須作業を現在の呼び出し内で完遂する。レポートに未実行を記録するだけでfinalへ進めず、開始した検証の正常終了まで確認する。自動の自己ループは持たず、それでも実行可能な義務を残して応答を終えた場合は既存のABORTで失敗を露呈させる。再計画は実行可能な作業につながる計画変更に限る。回答が必要な場合の対話入力・再開は維持する。
- `.takt/config.yaml` のimplement・fix・ai-antipattern-fix共通の検証規則では、ユーザー要求または採用済み計画が明示要求する検証を実行対象に含める。無関係な全体検証の抑制は、明示された必須検証を禁止する条件にしない。
- `development-remediation` の各版と共有の `review-remediation` は、`fix-plan → investigate → fix-plan` を持つ。調査対象は現在採用されている指摘に限定し、未確定の原因による本番修正はしない。反復調査は既存の loop monitor で監視する。
- `fix-investigation.md` は実験条件、コマンド、反復回数、観測値、否定した仮説、残件、一時的な変更を引き継ぐ。
- 実装証跡を引き継ぐ際は、元の実行記録と対象の同一性を記録する。失敗、未実行、同一性不明、影響する変更がある結果は成功として引き継がない。工程ごとの再実行が明示されていれば従う。
- 受入条件保持の手順は `preserve-acceptance-conditions.md` に集約し、実装・再計画・修正・裁定・検証で合成する。同じ修正計画へ二重に注入しない。

## 検証方法と限界

`development-loop-routing.integration.test.ts` は配布用の定義とファセットを実際のローダーで解決し、エンジンで継続・再計画・停止・局所調査の往復を検証する。エージェントと意味判定はテストダブルなので、モデルの判断精度を証明するものではない。

`eval/cases/completion-scope-routing.yaml` に、実行記録から抽出した smoke 残件、局所調査、観測能力の不足と対照例を追加した。日本語・英語の Phase 3 プロンプトは配布 YAML から生成する。タグ形式と構造化形式の両評価で使用できる。

以下のPhase 3評価は、自己ループ撤回前の設計を評価した歴史結果であり、現在の実装方針の成功率として扱わない。固定14ケース×日英×新旧を Claude Opus 5、Codex Astra xhigh、Kimi Code k3 で比較し、当時の期待遷移一致が各モデル旧12/28から新28/28へ変わった。自己ラベルが事実と矛盾する追加対照も、各モデル旧0/2から新2/2へ変わった。実ログ由来の入力は全文再生ではなく、確認事実を要約した資料である。

CodeRabbit対応時点の文言では、既存15ケースで3モデルとも日英30/30、追加3対照で各6/6だった。当時の108応答と、不成功の中間案、元の基準版証跡を保持している。現在の自己ループ撤回後に期待値だけを変えて再採点し、現行モデル評価として流用することはしない。

当時の構造化評価でも、provider schemaが入力要求の候補6を拒否する欠陥を契約のREDで確認し、上限修正後のGREENと実Codex providerの日英2応答を確認した。現在も入力要求の配線とschemaは維持するが、この過去の試行も現行の全判定条件を評価した結果ではない。

同一呼び出し内の完遂は、別領域の固定fixtureを使い、期待する実コマンドとツール結果・不変の検証スクリプト・生成ファイルを組み合わせて新たに評価する。Codexはexit_code=0、Claudeは非エラーのtool_resultを確認する。Kimiは個別exit codeが記録されないため、成功出力と不変checker・生成物による間接証拠として区別する。元runのiteration 16では、Phase 1の92ツール呼び出しにsmoke実行はなく、providerはsuccess=true、phaseはdoneだった。時間切れや環境障害による中断ではない。一般ゲートの限定と明示義務の衝突は確認できるが、当時のモデルが省略した内的理由は断定しない。新しい評価の再現範囲と結果は評価記録に分離する。

この実ツール評価では、条件付きgateが明示義務と競合する別領域ケースと、単純に検証だけが未実行のケースを新旧で固定した。ClaudeとKimiは旧2/2・新2/2、Codex Astra xhighは旧1/2・新2/2。Codexが旧版で検証を省略してfinalした同一ケースに対し、修正版は実行・正常終了・生成物を揃えてからfinalした。単純な作業漏れは旧版でも再現せず、そのケースは回帰確認に限る。
